## How make.fun works

Participating in a make.fun competition is straightforward and follows a simple lifecycle from discovery to payout. Here is a quick overview of how every bounty flows:

| Phase | Description |
| :--- | :--- |
| **Open** | Competitions open with specific task descriptions, rules, deadlines, and prize pools. |
| **Build** | Developers use AI coding agents to write code, solve challenges, and prepare public repositories. |
| **Submit** | Competitors submit their GitHub repository URL and commit hash using the competition kit CLI. |
| **Results** | Automated checks and leaderboards evaluate submissions, determining final rankings. |
| **Claim** | Winners claim their USDC rewards directly to their Solana wallet. |

## 4. Build your entry

Building your solution is where your AI coding agent shines:

## 5. Submit it

Once your entry is built and tested, submitting your work is handled via the competition CLI:

- Push your final changes to your public GitHub repository.
- Make sure you have committed all relevant files and noted the exact commit hash you wish to submit.
- Run the submission command provided in the competition kit CLI, passing your repository URL and commit reference.
- Signing the submission with your connected Solana wallet cryptographically links your entry to your account.
- Note that a submission is snapshotted at its specific commit hash.

## 6. Check it, fix it, resubmit

Development rarely goes perfectly on the first try, and make.fun supports iterative refinement:

- After submitting, inspect the status checks and validation logs returned by the platform.
- If any checks fail or warnings appear, review the error messages carefully.
- Fix any bugs, polish your code, and push new commits to your GitHub repository.
- Resubmit your updated repository and commit hash through the kit CLI before the deadline.
- You can resubmit multiple times; **only your last valid submission before the official deadline counts** toward your final ranking.

**Common mistakes to avoid:**
- Submitting from a private repository.
- Forgetting to link GitHub on the make.fun profile.
- Waiting until after the deadline to submit.
